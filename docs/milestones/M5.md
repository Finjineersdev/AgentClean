## Status (20 Nov 2026)

Steps 1–9 are done, one commit each. Checks at the end: engine fmt, clippy,
113 core and 21 CLI tests, `rules-check`; 15 Swift tests; the Debug
walkthrough (32 checks) in dark and light; all 11 UI tests including the
accessibility audit on every screen, run locally.

41 s in Debug, with 8 s of CPU. It waits on the disk, so parallel walking is
the only lever left; the first result arrives after 0.4 s (N4 holds).

## Safety notes

- Step 2 lets a pin end. That only ever re-allows what the guard already
  allows; the guard, deny list and quarantine are unchanged.
- Step 3: a repository's own file can only take folders away from cleaning.
  User rule files are the user's, but they still pass `rules-check` and the
  guard, and cannot reuse a built-in rule id.
- Step 5: the schedule calls the same `clean` with no `--include-caution` or
  `--include-active`; pinned projects are refused by the engine as always.
