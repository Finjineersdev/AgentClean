# M2: discovery and catalogue

Goal: `agentclean scan` finds every project under the chosen folders, says
why each is idle or active, and reports what can be reclaimed, for about
eleven ecosystems, with JSON output the Mac app can consume in M3.

Work the tasks in order; each ends with the four engine checks green and
`docs/SAFETY-SPEC.md` updated if an invariant changed. Keep tasks to one or
two pull requests each.

## M2.1 Test debt from M1

- Add `engine/fuzz/` (cargo-fuzz) with targets for `rules::parse` and the
  quarantine manifest loader (`Store::load` on arbitrary bytes). No panics,
  no paths escaping the store.
- Run `cargo-mutants` on `guard.rs`, `deny.rs`, `quarantine.rs`; add tests
  until no mutant in a safety check survives. Record the command in
  `CONTRIBUTING.md`.
- Add a nightly workflow for fuzzing (time-boxed) and mutation testing.
- Pin GitHub Actions in `engine.yml` to commit SHAs.

Done when: fuzz targets run 10 minutes each without findings; zero surviving
mutants in guard and deny logic.

## M2.2 Rule schema 2

Schema 1 cannot express Xcode or .NET markers (`*.xcodeproj` is a folder,
`*.csproj` a pattern) or require evidence for generic names.

- `detect.any_files` (plain names), plus `detect.any_glob` limited to a
  single `*` in the final component (`*.csproj`, `*.xcodeproj`), and
  `detect.any_dirs`.
- `detect.exclude_if` to stop double matches (Flutter's `android/` is not a
  separate Android project).
- Per artifact `requires`: evidence that must exist for that path to be a
  candidate, for example `dist` only with a build script in `package.json`,
  `bin` and `obj` only beside a `*.csproj`.
- Fixtures: `engine/rules/fixtures/<rule id>/match/...` and `.../nomatch/...`
  as small directory trees; a test asserts each rule's expected candidates.
- Keep schema 1 files loading; migrate the three existing files.
- Update `docs/RULE-SCHEMA.md`.

Done when: the linter rejects patterns with more than one `*`, path
separators in globs, and evidence paths that escape the project.

Shipped with these differences from the table:

- `__pycache__` is matched only in the project root. Nested ones need a
  recursive pattern the schema does not have; decide in M2.4.
- Xcode `build` is left out: the legacy build folder holds only folders, and

  `venv` and `.venv` need `pyvenv.cfg`; Go and PHP `vendor` need
  `modules.txt` and `autoload.php` inside.

## M2.4 Discovery

New module `discover.rs`.

- Input: scan roots (default: the home folder, skipping `Library`, `.Trash`,
  `Pictures`, `Music`, `Movies`, `Applications`), max depth, user exclusions.
- Detects a project where any rule's markers match; keeps walking below a
  project for nested workspaces and monorepos.
- Never descends into: artifact folders already matched, `.git` and other VCS
  folders, bundles (`*.app`, `*.xcodeproj`, `*.xcworkspace`), symlinks,
  other volumes, or the quarantine store.
- Streams results (a callback or channel) so the app can show projects as they
  are found; reports skipped and unreadable folders with reasons.
- Bounded: depth limit and per-root entry limit, both configurable.

Tests: fixture trees with nested workspaces, symlink loops, unreadable folders,
a bundle, a project inside `node_modules` (must not be reported).

Done when: on a fixture modelled on the owner's layout (`dev/`,
`development/`, `Mobile Projects/`, `Laravel Projects/`, `pythonprojects/`,
`websites/`) every project is found.

Shipped as `discover::discover(rules, &Options, callback)`. Beyond the list
above: hidden folders are not entered unless they are a root (tool caches such
as `~/.cargo` are full of manifests), `~/go/pkg` joins the home skips, and a
folder holding a marker that `exclude_if` sends to the parent project (Flutter's
`android/`, `ios/`) is not entered. Default depth 16, 2,000,000 entries per
root. On the owner's real folders: 242 projects in under a second, most of them
packages inside the Flutter SDK checkout (`~/development/flutter`), a likely
default exclusion for M2.6.

## M2.5 Activity and verdicts

New module `activity.rs`.

- Signals: last commit time (git with the hardened flags from
  `guard::check_untracked`), newest modification time of non-artifact files
  (bounded walk, artifact folders skipped), processes whose working directory
  is inside the project (via `sysinfo` or `libproc`; never by name alone).
- Verdict: Active, Idle, Dormant, with a one-line reason built from the
  signals; thresholds configurable (defaults 14 and 90 days, to be confirmed).
- Pins and "never clean" stored in a config file
  (`~/Library/Application Support/AgentClean/config.toml`, XDG on Linux).
- Guard integration: a pinned or active project yields `Refusal::ActiveProject`
  (invariant I15) unless an explicit override flag is passed.

Done when: I15 is in `SAFETY-SPEC.md` with tests.

## M2.6 `scan` command and JSON

- `agentclean scan [roots...] --rules DIR [--json]`: projects with verdict,
  reasons, candidates, sizes, refusals.
- `--json` on every command; schema documented in `docs/CLI-JSON.md` with a
  `schema_version` field; snapshot tests.
- `clean` accepts `--from-scan` style selection so the app can pass exact
  choices; still dry run without `--execute`.
- Ship the rules inside the binary (`include_str!`) with `--rules` as an
  override, so the CLI works without the source tree.

## M2.7 Cross-volume decision

Projects on another volume are skipped today. Options: a quarantine folder per
volume (`<volume root>/.agentclean-quarantine`, created on first use), or
move to the system Trash for those volumes. Write an ADR, implement the
choice, and test with a second file system (a disk image on macOS, tmpfs on
Linux).

## Out of scope for M2

The Mac app, global caches, Docker, scheduling, the character. Do not touch
